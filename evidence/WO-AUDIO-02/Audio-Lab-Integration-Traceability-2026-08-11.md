# WO-AUDIO-02 — Integration Traceability (SR-01 .. SR-10)

**Date:** 2026-08-11

| Finding | Severity | Implementation correction | Test ID(s) | Result / evidence |
|---|---|---|---|---|
| **SR-01** — Failed microphone/file setup can leave UI and engine source states inconsistent | HIGH | `switchSource()` in `audio-lab-engine.js` fully prepares the candidate (permission grant / file decode) **before** any teardown of the current valid source; a rejection leaves engine state untouched. Controller reverts the radio-button selection to `lastConfirmedSourceType` on any `switchSource` rejection. | UT-07 (4 tests: failed mic, failed file after a non-generator prior source, invalid file rejected pre-decode, successful commit) | PASS — `test/audio-lab/engine.test.mjs`; see Automated Test Report §2, §4 |
| **SR-02** — Microphone routed to speakers, can start at unity gain (privacy/feedback risk) | HIGH | Corrected graph inserts a `monitorGateNode` between the analyser and destination; `computeMonitorGain('microphone', ...)` is unconditionally `0` with no user control to override it. The microphone signal still reaches the analyser (continuous analysis) but never the destination. | UT-09 (pure `computeMonitorGain` + engine-integration test reading the real fake gain node's value across mic/generator/playing transitions) | PASS — `test/audio-lab/pure-helpers.test.mjs`, `test/audio-lab/engine.test.mjs`; see Implementation Report §3 "Corrected audio graph" |
| **SR-03** — Stop/mute/gain/channel/phase controls do not consistently govern microphone/file sources | HIGH | `setOutputControls()` updates the one shared master-gain/channel/phase graph regardless of `activeSourceType`; the controller calls it from every gain/channel/phase/mute UI handler, not only generator handlers. | UT-10 (pure `computeChannelPhaseGains` + engine-integration test asserting the real left/right phase gain nodes after `setOutputControls`) | PASS — `test/audio-lab/pure-helpers.test.mjs`, `test/audio-lab/engine.test.mjs` |
| **SR-04** — dBFS/threshold logic samples canvas pixel positions, lacks input validation, no calibration statement | MEDIUM | `findBandPeak()` iterates every real FFT bin in `[minFrequencyHz, maxFrequencyHz]` (mapped via true `sampleRate / fftSize` spacing), independent of any canvas pixel width. `validateThresholdBand()` rejects NaN, non-positive, reversed, and Nyquist-exceeding bands before the value is used. Spectral-dB meaning/limitations are documented in the Implementation Report (default `AnalyserNode` decibel range, no absolute-dBFS calibration claim). | UT-02, UT-03, UT-04 | PASS — `test/audio-lab/pure-helpers.test.mjs` |
| **SR-05** — Perpetual canvas loop has no visibility/cleanup/DPI/responsive management | MEDIUM | `audio-lab.js` render loop starts only after explicit engine activation, pauses on `visibilitychange`, and fully tears down (loop cancelled, `ResizeObserver`s disconnected, `engine.teardown()` called) on `pagehide`. Both canvases use `ResizeObserver` + `devicePixelRatio` for backing-store sizing; the waterfall's cached line `ImageData` is invalidated on resize. | No unit test (requires a real DOM/rAF/ResizeObserver browser environment) | **BROWSER VALIDATION PENDING** — BT-15, BT-16, BT-17. Implementation reviewed against the requirement in Implementation Report §3 "Canvas lifecycle"; not independently executed in this environment. |
| **SR-06** — Export settings include ignored fields; 32-bit WAV mode has an invalid format tag | MEDIUM | `validateExportConfig()` accepts exactly one configuration (96 kHz / 24-bit / stereo / generator source / an approved duration) and rejects everything else with a descriptive error **before** any `OfflineAudioContext` is constructed. The encoder (`encodeWavPcm24`) only implements the one supported bit depth — no invalid float/PCM tag mismatch is possible because no other tag exists. | UT-14, UT-15, UT-16 (incl. a spy proving the offline context is never created for a rejected config) | PASS — `test/audio-lab/wav-encoding.test.mjs`, `test/audio-lab/engine.test.mjs` |
